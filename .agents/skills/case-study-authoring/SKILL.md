# Case Study Authoring Skill — The One Day

Use this procedure when authoring or refining technical case studies for **The Engineer** or journal entries for **The One Log** and creative pillars.

---

## Procedure

### Step 1: Fact Verification & Source Attribution

1. Cross-reference all technical claims, project details, roles, and dates against the owner's authoritative resume.
2. If specific metrics (e.g., latency reduction, throughput numbers) are not documented in the resume, ask the owner for confirmation or omit unverified numbers.
3. For creative or personal entries (sketches, yoga poses, photography), only use genuine assets supplied by the owner. Note the approximate year, medium, or context where known.

### Step 2: Anatomy of an Engineering Case Study

Structure each engineering project write-up with clear, compelling technical narrative:

1. **Header & Context:**
   - Project Title & High-Level Summary (1–2 sentences).
   - Role / Contribution (e.g., Full Stack Engineer, Architecture, Lead Developer).
   - Core Technologies / Architecture stack.
   - Live URL or GitHub Repository (if public).
2. **Problem Statement:**
   - What real problem or user need did this solve?
   - What technical or architectural constraints existed?
3. **Architecture & Technical Solution:**
   - Why were specific tools, frameworks, or database choices made?
   - What trade-offs were considered?
   - How did the implementation solve the core challenges (e.g., concurrency, caching, data consistency, UI responsiveness)?
4. **Outcomes & Concrete Learnings:**
   - Measurable or qualitative outcomes.
   - Key engineering insights, technical lessons, or things that would be approached differently in retrospect.

### Step 3: Editorial Tone & Writing Style

- Maintain a direct, thoughtful, and articulate engineering voice.
- Avoid promotional fluff, marketing hyperbole, or buzzword soup.
- Explain technical complexity with clarity and respect for the reader's time.

### Step 4: Formatting & Code Presentation

- Write content in clean Markdown or MDX.
- For code snippets, include accurate language tags (`tsx`, `ts`, `sql`, `json`) and keep snippets focused on the core concept rather than dumping entire files.
- Include informative captions under architecture diagrams or UI screenshots.
